## 实际游戏变化

### 670 名资料武将可加入当前局面

菜单→全国资料 / 核验目录→搜索武将→加入局面→选择己方据点→预览→确认加入。这是显式 PK 编辑，标记当前局面已编辑，不是付费登用，也不声称恢复了任何官方开局。

- 能力、六兵科适性、性别、特技和舌战性格来自已有固定来源表，全部670人都可以进入实际 World。
- 可选择按资料年份登场并载入生卒；未来人物保留为未登场，指定年正月在所选据点以在野身份出现。可取消日期限制立即加入，此时不注入生卒。
- 来源的自然死 `O` 才用于本工程预计寿终年；`X` 的历史卒年保留在资料目录，不当作自然寿命。此处理是防止误用资料的工程策略，不是对原版寿命算法的确认。
- 可选择连接本局存在且 ID/来源名称或批准别名一致的人物关系。不同阵营不妨碍记录亲子；人物未在本局不创建幽灵武将。已有父母/配偶等冲突会拒绝整次导入，保留玩家编辑。
- 导入先在存档副本上验证；取消、重复导入、编号冲突、过期预览均不修改局面。实际状态存进v15的既有关系、生卒、对局人物和编辑段，读档不会重新查资料覆盖玩家修改。
- “武将资料演练”更新为r2，明确启用生卒、性格、在场人物关系；原“区域争雄”等原创开局以及旧存档不自动增加这些数据。自然死亡仍默认关闭。

### 869 条关系从原文进入规则

离线构建仅以原表**唯一且完全一致的姓名**解析目标，再输出稳定 ID。运行时不按同名猜测。

| 原表记录 | 处理 |
| --- | --- |
| 869条可明确绑定的关系 | 输出 `relations.tsv`，在人物实际存在时接入亲子、夫妻、结义、亲爱和厌恶规则 |
| 99条歧义或外部人物 | 保留原文、候选ID和隔离原因，继续待核验 |
| 刘备“义兄=刘备”1条 | 识别为结义组锚点，不生成自指；关羽、张飞对刘备的关联组成闭合三人组 |

例如来源结义会影响实际编队能力贡献；厌恶会影响登用和AI选副将；来源性格影响舌战；已知亲子参与现有继承顺序。对应的数值系数仍是工程规则。来源的血缘编号、相性以 `profiles.tsv` 保留，**未冒充已实现全部血缘/相性公式**。同名李丰、张南、马忠不靠历史常识自动消歧。全表导入和全部869条关系的实际落地通过核心测试。

## AI

- 同一部队的一轮战略目标比较共用一次加权寻路，可以同时评估多个敌城、附近敌军或可接纳的己方退却据点；不再针对每个城市重新遍历地图。
- 搜索仍考虑当前兵装、水陆、地形、占格、毒火、栈道和敌军控制区；移动执行仍使用玩家同一命令的行动力、路径及过期校验。路径结果仅用于本次决策，不跨命令缓存。
- 选主将和兵科时一并比较编队收益；副将按实际能力贡献、最高适性、智力和战斗特技选择，重复特技不重复加分，城务专用特技不单独占用出阵名额，保留行政人才，避开相互厌恶的人物。
- 神算/虚实等与百出、连环的配合显式参与评分；“神算＋百出＋连环”测试会排除编号更靠前的富豪武将。评分是工程策略，不是光荣AI逆向公式。
- 在200×200源格（299×200轴向）、87据点、670武将的**合成性能夹具**上，86个敌城只触发1次搜索、展开37839格；本地单次测试约84—121ms。它不是原版地图、整旬耗时、手机帧率或ARM实测结果。
