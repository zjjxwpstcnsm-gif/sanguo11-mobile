# 剧本与地图数据格式 v1

本轮建立数据载入和验证管线，尚未取得或核对原版全量数据。两个内置包均标记 `engineering-original`，不代表原版历史开局。M1 的原版版本冻结、完整内容清单和来源核对仍未完成。

## 文件与标识

- `core/src/main/resources/scenarios/index.txt`：每行 `scenario-id SHA-256`，校验同名 properties 文件的原始 UTF-8 字节。
- `*.properties`：只包含静态字段，无脚本、反射类名或可执行表达式。
- `id` 是稳定剧本标识，`revision` 为数据修订；修改数据后同时更新校验值和修订号。
- 城池和武将使用稳定整数 ID，不依赖数组顺序。`city.N`、`officer.N` 的 N 只负责遍历，记录首列才是实际 ID。
- 势力 ID 目前为数据包内连续的 0～N−1；同一包的修订不得重排既有势力编号。存档内嵌完整势力表与局面，不依赖新安装的数据文件。
- `source=engineering-original` 是当前唯一开放的来源等级。未来接入核验数据时，须扩展按字段记录的版本/证据/差异格式，不能仅把字符串改为“原版”。SHA-256 用于一致性检查，不证明数据来源或原版正确性。

## 字段

| 字段 | 意义 / 约束 |
|---|---|
| format | 固定 1；未知版本拒绝 |
| id / name / revision / source | 稳定 ID、中文名称、修订号、来源等级 |
| year / month | 开局年份及月份，默认上旬开始；1～9999年，1～12月 |
| width / height | 1～128格；轴向六角坐标 q/r |
| factions / faction.N | 2～32家势力及名称，不允许重名 |
| terrain.R | 第 R 行，共 width 个字符；P 平原，F 林地，M 山地，W 水面 |
| cities / city.N | 城池数及记录 |
| officers / officer.N | 武将数及记录 |

城池记录（15列，用 `|` 分隔）：

`id|名称|q|r|势力ID|金|粮|兵|治安|气力|城防|枪|戟|弩|马`

武将记录（9列）：

`id|名称|势力ID|城池ID|统率|武力|智力|政治|魅力`

城市 owner=-1 为中立城；武将 owner=-1 可表示在野。可选 `talents` / `talent.N` 保存未被发现的人才，9列为 `id|名称|城池ID|统率|武力|智力|政治|魅力|登场旬数`。不包含关港、水军或完整外交。本格式没有假装包含未实现的完整武将字段。

## 验证

读取上限 1 MiB。拒绝缺失、重复、未知字段，越界数值，未知地形，地图行宽错误，重复ID，错误所属势力，跨势力驻城，无出口城池，以及不连通的陆路地图。图中地理连通的校验暂忽略城池占格，具体部队寻路仍受敌我城池和部队阻挡。

每个开局势力至少有城池与在城武将。加载失败不返回半成品局面，Android 仅在完整解析和验证后替换当前游戏。

## 存档 v4（兼容 v1/v2/v3）

继续使用 M0 的 magic、长度上限和 CRC 外壳。v2 在局面头后加入势力名称、玩家势力、开局日期、剧本标识、修订、来源与数据指纹，随后保存所有资源、武将、部队、行动与日志。

v1 解码补入原来的两势力和190年1月开局，数据指纹留空，下一次保存写入当前 v7。仓库保留改造前实际产生的 `m0-v1.sg11.b64` 夹具验证兼容；不是用新编码器模拟旧版本。未知未来版本、截断、CRC不符、引用错误和伪造胜者均拒绝。

手动槽1仍使用 `manual.sg11`，新增 `manual2.sg11`、`manual3.sg11`；自动槽保持 `auto.sg11`。


v3 在部队记录之后、战报之前加入设施与战略任务。设施保存编号、所属城池、类型、地块、施工武将和剩余旬数；任务保存编号、所属势力、武将、起点/目的地、当前位置、任务种类、金粮兵和四种兵装。唯一编号计数器随存档持久化。v1/v2读取时初始化空战略层，不要求旧数据包仍安装。新增真实v2夹具`m1-v2.sg11.b64`与原v1夹具一起做迁移续局回归，详见[战略层说明](STRATEGY_LAYER.md)。

解码与编码均验证设施位置/工期/城池引用和武将占用、任务货物边界/类型/引用，以及同一武将不能被重复派遣。资源满仓等待中的任务可正常保存，并在恢复后的回合继续检查空间。存档版本兼容不代表Android签名兼容；不要为覆盖安装失败而直接卸载仍有重要存档的旧应用。


v4 在 Domestic 字段之后、日志之前追加 STR4 扩展：随机数状态、城市兵源/太守、武将忠诚/身份/长期任务/褒奖记录、隐藏人才与关系修正。真实 v3 夹具含建设和在途运输；旧档沿用原局面，不注入新人才。详见 [人员存档与迁移](handoffs/agent-strategy-officer-v04.md)。

## v0.7 可选军备字段

`arsenals=N`、`arsenal.i=cityId|冲车|井阑|木兽|投石|楼船|斗舰`：每类0～100件/艘。
`aptitudes=N`、`aptitude.i=officerId|枪|戟|弩|骑|兵器|水军`：每类0～3（C/B/A/S）。未提供时保留旧默认B，额外军备默认为0；重复与不存在的引用均拒绝。


## 历史存档 v7（兼容 v1～v6）

版本号唯一由 Agent 1 升级为7。v5 CampaignSave、v6 ArmySave 原布局保留；v7 在 ArmySave 后、日志前追加 RulesSave。RUL7标记0x52554C37，单位记录保存ID、移动预算、已用预算及燃烧来源倍率，火场记录保存地块q/r、源倍率与火种标记，武将记录保存稳定ID、UTF特技ID及性别。完整边界校验见RulesSave。

真实v6夹具来自未修改固定基线编码器，含三将/舰船/火场及制造、研究、培养、运输进行态。v1～v6不注入新资料人物或特技，随机数和资源保持原值。v7允许未知稳定特技ID留在档内；读取不调用ContentCatalog，不因资料包移除而重建开局。

资料ID `skill-000`～`skill-099` 保留为来源台账，ContentRuntime逐项校验并映射到 `san11.*` 规则ID。仅新建明确的资料演练时加载18人的技能/性别，后续均以档内运行状态为准；未解析关系、生卒登场、宝物与事件仍不触发规则。

## 历史存档 v8（兼容 v1～v7）

v7 的所有节保持字段顺序，在 RulesSave 后、日志前追加 GovernmentSave（标记 0x474F5638）。包含功绩、UTF官职名、军师、UTF委任方针、俘虏关押/俘获/尝试日期、按任务ID对应的水陆运输方式。旧运输主节的护送兵数量可因截击改变，类型布局不变。所有新增数量、重复ID、归属、独占官职和任务锁均校验后接受。

俘虏的武将原势力不变，cityId/unitId均为-1，另以关押城引用定位；不能同时承担其他任务。部队兵力存储校验上限扩到15000，出征与补给另执行主将的官职容量校验。未授官沿用既有沙盘10000上限。

读v1～v7时新增军政为空，运输为旧陆路类型，不重新载入资料包。`legacy-v7.sg11.b64` 在本轮改编码器前从已合并v0.8代码生成，用于实际迁移回归。移动预览快照自动包含新增字段，任官、俘虏处置或补给后，旧移动确认会失效。

## 历史存档 v9（兼容 v1～v8）

在GovernmentSave后、日志前追加ContestSave，标记0x43545339。保存下一会话ID、最近结果、显式人物性格/话术/携物配置、负伤等级与恢复旬、可空的单挑或舌战会话。会话保存归属、引用、创建旬、操作修订号及逐人状态；舌战还保存手牌与对方已选牌。随机数继续使用原Strategy字段，读取不重新抽牌。

在途单挑的编队、相邻/陆上条件、行动锁、体力/斗志与已加入状态会被校验；舌战的目标范围、心理/台阶/手数/话术许可/AI合法选牌与待结算胜负也会被校验。终局结算会清除会话，重复提交返回失败。真实v8夹具由修改前编码器生成。

可选剧本字段`contest-profiles`每条为`武将ID|CALM/BOLD/TIMID/RASH|话术位掩码0..31|携物位掩码0..63`。可选`initial-units`每条为`ID|势力|主将|副将逗号串或-|兵装枚举|舰船枚举|q|r|兵|粮|气力`。存在初始部队时驻城总量与部队数量各自是开局快照，不执行扣库出征命令。完整规则边界见CONTESTS_V0_10.md。

## 当前存档 v10（兼容 v1～v9）

在ContestSave后、日志前追加AbilitySave，标记0x504B3130。按势力保存五处隐藏能力的具体节点ID、已研究节点、已使用培养次数和至多一项能力研究（据点、节点、剩余旬）。培养记录保存所属势力、据点、武将、节点、开始数值和原特技；剩余旬继续使用武将任务字段。每位武将五项基础能力的实际研究成长累计独立保存。

解码校验隐藏槽唯一性、已学/在研节点及全部前置、次数上限、研究归属、三类培养互斥、驻地/俘虏/占用、培养起点与成长范围。隐藏选项在新局初始化时抽取，读档使用存下的选择，不重新抽签。当前气力有效范围扩至120；实际训练和出征上限仍受熟练兵研究控制。

真实`legacy-v9.sg11.b64`由修改前v0.10编码器产生，包含进行中的旧式培养；升级继续原工期与奖励，新培养改走PK规则。旧档无法还原既往培养累计，只累计升级后的实际成长。入口、限制和未核验细节见[PK研究与培养](PK_V0_11.md)。
