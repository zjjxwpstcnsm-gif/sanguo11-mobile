# 剧本与地图数据格式 v1

本轮建立数据载入和验证管线，尚未取得或核对原版全量数据。两个内置包均标记 `engineering-original`，不代表原版历史开局。M1 的原版版本冻结、完整内容清单和来源核对仍未完成。

## 文件与标识

- `core/src/main/resources/scenarios/index.txt`：每行 `scenario-id SHA-256`，校验同名 properties 文件的原始 UTF-8 字节。
- `*.properties`：只包含静态字段，无脚本、反射类名或可执行表达式。
- `id` 是稳定剧本标识，`revision` 为数据修订；修改数据后同时更新校验值和修订号。
- 城池和武将使用稳定整数 ID，不依赖数组顺序。`city.N`、`officer.N` 的 N 只负责遍历，记录首列才是实际 ID。
- 势力 ID 目前为数据包内连续的 0～N−1；同一包的修订不得重排既有势力编号。存档内嵌完整势力表与局面，不依赖新安装的数据文件。
- `source=engineering-original` 是当前唯一开放的来源等级。未来接入核验数据时，须扩展按字段记录的版本/证据/差异格式，不能仅把字符串改为“原版”。SHA-256 用于一致性检查，不证明数据来源或原版正确性。

## 字段

| 字段 | 意义 / 约束 |
|---|---|
| format | 固定 1；未知版本拒绝 |
| id / name / revision / source | 稳定 ID、中文名称、修订号、来源等级 |
| year / month | 开局年份及月份，默认上旬开始；1～9999年，1～12月 |
| width / height | 1～128格；轴向六角坐标 q/r |
| factions / faction.N | 2～32家势力及名称，不允许重名 |
| terrain.R | 第 R 行，共 width 个字符；P 平原，F 林地，M 山地，W 水面 |
| cities / city.N | 城池数及记录 |
| officers / officer.N | 武将数及记录 |

城池记录（15列，用 `|` 分隔）：

`id|名称|q|r|势力ID|金|粮|兵|治安|气力|城防|枪|戟|弩|马`

武将记录（9列）：

`id|名称|势力ID|城池ID|统率|武力|智力|政治|魅力`

城市 owner=-1 为中立城。当前不支持在野、未登场、关港、水军或外交关系；这些仍在完整功能表中追踪。本格式没有假装包含未实现的完整武将字段。

## 验证

读取上限 1 MiB。拒绝缺失、重复、未知字段，越界数值，未知地形，地图行宽错误，重复ID，错误所属势力，跨势力驻城，无出口城池，以及不连通的陆路地图。图中地理连通的校验暂忽略城池占格，具体部队寻路仍受敌我城池和部队阻挡。

每个开局势力至少有城池与在城武将。加载失败不返回半成品局面，Android 仅在完整解析和验证后替换当前游戏。

## 内置包来源与差异

| 包 | 内容 | 来源 / 差异 |
|---|---|---|
| m0-skirmish r1 | 15×12，3城6将，刘备军/曹操军 | 从 M0 内嵌样例搬迁；地图与数值保持测试场基线 |
| regional-sandbox r1 | 28×23，9城18将，刘备军/曹操军/孙权军，208年9月 | 本项目原创布局与开局归属；历史人物和地名用于标识，所有能力值、位置、资源及同时登场组合均未按原版/史实核验 |

目前没有收录全量城关港、全国地形、原版武将库或官方剧本；不能以这两个包推断 M1/M2 全部完成。

## 存档 v2

继续使用 M0 的 magic、长度上限和 CRC 外壳。v2 在局面头后加入势力名称、玩家势力、开局日期、剧本标识、修订、来源与数据指纹，随后保存所有资源、武将、部队、行动与日志。

v1 解码补入原来的两势力和190年1月开局，数据指纹留空，下一次保存写入 v2。仓库保留改造前实际产生的 `m0-v1.sg11.b64` 夹具验证兼容；不是用新编码器模拟旧版本。未知未来版本、截断、CRC不符、引用错误和伪造胜者均拒绝。

手动槽1仍使用 `manual.sg11`，新增 `manual2.sg11`、`manual3.sg11`；自动槽保持 `auto.sg11`。
