# 地图专题：错列方格、原图配准与87据点对照

基线是正式主线 v0.52.0，`63a3d5e3f946145fb8b5e4a52b29d5d3cccaf140`。这是地图专题的有限增量，不是全国地图100%还原版；不覆盖另一个Agent的战报/出征功能。

## 本轮做了什么

正式Android地图的蜂窝六角形外观改为40×40错列方格，统一主地图、远景缓存、点选逆变换、领地边界、岸线、道路接点、栈道木纹朝向、小地图和摄像机裁剪。六向寻路、距离、战法及全部现有地图数据不变。原有18项地图/图集指纹保留；没有替换美术，没有把原图当游戏背景。

`TileGeometry`是绘制/点选的统一几何来源。方形上、下边各分为两个与邻格相接的线段，左右各接一格，总计仍为六邻接；不能增加所谓第七/第八个对角邻居。旧立方坐标取整会在方格四角误选邻格，已同步移除，不能只改轮廓。

原图采用**列错列**，现行剧本是**行错列odd-r**。本轮只纠正外观并保持既有拓扑，不冒称已经完成原生列错列的全国规则迁移。若后续迁移，必须重核港口上下船、关口防绕行、城际路网、战法方向及存档；不能将原生坐标直接当odd-r使用。

## 原图与更正后的配准

用户提供 `MAP_SAN11.jpg`：7200×6752，SHA-256 `a5a4e8c7f9785b6fbadc8487508ff6c937dcef2d782b099f2e876e48d167d4e0`。

作者 X GOD / 艾克軋德，2018-05-21。作者说明：绿色是从小地图放大的行政边界且有偏差；红格须“难所行军”；建筑黑边是为方便辨认额外添加。不能将绿线视为山脊/道路，也不能把黑边推定为精确碰撞边界。来源：https://xgodgame.blogspot.com/2018/05/11.html

复用v50的42个城市图标像素锚点，显式使用原生列错列 `(x, y + 0.5*(x%2))` 拟合图像坐标。对同一组锚点的拟合残差RMS由忽略错列时的7.942像素变为2.367像素，中位数0.753像素；最大仍约11.592像素。这是**同组锚点拟合残差**，不是独立验证的全地图绝对误差，也不是建筑占地精度。

现行全国图是100×100缩尺，不是原生200×200格的完整逐格导出；本轮未擅自扩图。狭窄支路、细河岸和大型建筑占位需要原生尺度数据设计，不能靠继续放大一个单格图标解决。

## 城池/关卡多格占地：核查结论和未完成项

原图中的长安、潼关等图标确实跨格，但仅凭总览图，不能断言统一“城7格/关3格”。本轮**没有**写入未经验证的格数，也**没有**将放大图片冒充逻辑多格支持。

当前 `World.City.hex`、`CityRoster.positions`仍是中心单格。后续正式多格迁移至少必须一并完成：

- 一个据点ID对应占地集合和外缘可接近格；`cityAt`/点选、部队阻挡和部署从同一索引取数。
- `World.siegePositionError`、`Army.tacticPositionError`、`CityDefense`以目标占地最近边缘计算合法射程，所有占地格共享同一耐久与归属。
- `Army.deploy/canEnterSite`、`MarchOrders`、`Domestic`运输到达、`Supply`邻近补给、`Fieldworks`修理和AI使用边缘而非中心邻格。
- 关墙朝向和两侧山体真正封锁通路，不能继续用扩大图标遮掩可绕行格；港口水陆边界保持现有合法上下船检查。
- 开发位、开局单位、保存/加载、索引失效和碰撞验证一并迁移；禁止吞掉现有591开发位，也不能旧档载入后让部队留在新城墙内。

逐区后续顺序：长安—潼关—函谷关—洛阳及黄河港群作为占地/关墙/港口的共同样板，然后晋阳—壶关—邺，汉中—阳平关—梓潼—剑阁，许昌—宛—新野—襄阳，江淮—江东，最后东北/南中细支路。每区必须同时核图、核通行、核战斗边缘，不能只移动图标。
