# 开发路线与架构

## 里程碑

| 阶段 | 可验收交付 | 退出条件 |
|---|---|---|
| M0 工程基础 | 规则内核、测试战场、Android触控、测试、APK CI | 可编译；基础规则和存档测试通过 |
| M1 规则与数据基线 | 版本锁定、完整命令/武将/城关港/兵装/剧本清单、地图格式 | 每项有出处和待核验标记；不填造全量原版数据 |
| M2 全国战略 | 全国地图、设施布局、人事、资源、后勤、完整剧本入口 | 能完整完成经营→出征→运输→攻城→回城循环 |
| M3 完整战术 | 战法、计略、设施陷阱、全兵装、适性、特技 | 位移/火焰/俘虏等交互对照用例通过 |
| M4 势力经营 | 外交、军团、技巧、PK能力研究、官职与关系 | 长期多势力模拟和任务时序验证 |
| M5 子系统与内容 | 单挑、舌战、事件、全剧本、决战、编辑器 | 各玩法独立可操作，结果正确回写战略状态 |
| M6 表现与发布 | 完整3D/音画、触控优化、真机性能、正式签名APK | 全范围验收，无未披露的功能替代或占位 |

不承诺未验证的工期或一次对话完成商业规模游戏；里程碑是工程推进顺序，不缩减最终要求。

## 架构选择

M0采用 Java 17 纯规则内核与原生 Android 客户端。规则不调用 Android API；所有行为在 `World` 校验，UI和AI使用同一套入口。固定整数规则方便重放与对照，当前伤害无需随机数。引入原版概率后需要可存档的随机状态，不能直接使用系统时间。

测试客户端使用Canvas绘制六角格，它不是最终3D表现方案。全国地图制作前，对OpenGL/游戏引擎渲染进行专项评估；规则通过数据状态独立存在，渲染替换不应重写回合逻辑。不在M0引入服务端、账户系统、联网对战或微服务。

当前地图和武将数据在 `DemoScenario` 明确标注测试来源；M1应提取正式数据包并引入稳定ID、外键校验、来源/授权、版本与校验值。不会通过随机生成几百个名字冒充原版武将库。

存档使用带版本、长度限制和CRC的二进制字段格式，不使用Java对象反序列化。失败加载不能覆盖当前局面。Android使用原子写入和独立自动/手动槽；后续增加迁移与导入导出。

Android当前固定 AGP 8.9.2 / Gradle 8.11.1 / JDK 17 / SDK 35 / minSdk 26。版本组合依据 [Android官方兼容表](https://developer.android.com/build/releases/agp-8-9-0-release-notes)。这是已知兼容基线，不声称是最新版本。当前不用NDK，ARM64和x86设备均执行同一份DEX代码。

CI保存调试APK，参见 [GitHub产物文档](https://docs.github.com/en/actions/tutorials/store-and-share-data)。调试签名仅用于阶段测试；不能声称具备正式版持续覆盖升级能力。
