# v0.3.0 历史验证记录

## 内核回归

`bash scripts/test-core.sh` 在本地 JDK21 按 `--release 17` 编译运行，共通过 **1196次断言**：CoreTest 189、ScenarioTest 282、DomesticTest 725。CI 的 Java17 环境也执行同样脚本和 `:core:check`。断言总次数包含长期对局循环，不等同于1196个独立测试用例；旧场景的执行次数会随AI和对局终止时点变化，原有测试方法并未删除。

新增重点：非法命令失败前后完整存档字节不变；施工占用武将、政治决定工期、取消/拆除/城破；设施实际收入和征兵/生产加成；运输即时扣货、跨旬移动、全部库存类型满仓等待与释放、失守自动改道、手动返回、道路阻塞与恢复；真实v1/v2存档迁移和确定性续局；三种玩家势力各最多45旬带内政/运输的确定性对局。

## Android 安装验证

保持 AGP8.9.2、Gradle8.11.1、SDK35、Build Tools35.0.0；CI构建APK/测试APK，执行Lint、数据包存在检查、API29 x86_64安装操作，再检查APK签名。主APK产物仅在上述门槛全部通过后上传。

平台 Instrumentation 通过可访问性节点定位真实屏幕坐标触控，不调用内核命令绕过界面。自动化核验实际自动存档，不只判断弹窗文本。

原有流程保留：选区域争雄/孙权军、定位建业、甘宁率3000弩兵出征、下一旬两个电脑行动、三个手动槽、新剧本后读回、损坏存档恢复、Activity重建。

新增流程：在柴桑选择市场/周瑜/开发地并开工；孙权调动至建业；鲁肃运输默认5000粮、1000兵、1000枪兵装至建业；查看在途任务；存槽3、Activity重启、推进一旬再读回原任务；推进到两位武将和货物抵达、市场建成，检查一次入库。运输表单为可编辑数量输入；当前UI测试提交默认数量，自定义参数及错误值由内核测试覆盖。

首次运行34754890197在重复城池定位时发现侧栏未复位，城市标题仍在可视区外。已修正显式定位、读档、新局、地块/任务导航和地图点选后的侧栏复位，保留原失败断言重新运行；不是通过去掉断言使测试通过。

运行 `scripts/smoke-android.sh` 仅使用专用测试设备，脚本会清空该设备的测试应用数据。不要在保存重要存档的手机上执行这个脚本。

## 未覆盖范围

API29 x86_64自动化测试不代替ARM64真机测试。不同手机分辨率/安全区、多指缩放与误触、系统杀进程、长时功耗/温控、稳定签名覆盖升级仍待实测。Activity重启/重建测试不等同操作系统低内存杀进程测试。

目前每次CI使用临时调试签名，不能保证覆盖旧APK。存档版本向后兼容与APK签名兼容是两件事。不要因安装冲突直接卸载存有重要进度的旧应用；需要先落实安全导出/持久签名方案。签名私钥不得提交仓库。
