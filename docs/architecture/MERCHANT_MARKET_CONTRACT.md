# R26 商人行情、数量与v35兼容契约

本增量由玩法会话维护；app/声音/3D文件没有修改。继承R25完整源码及七格位移修复，原成长/官职资源不替换。

## 正常命令与只读预览

`Campaign.previewTrade`和typed `GameApi.preview(TradeCommand)`共用TradePlan，完整校验、报价、经验/能力、钱粮、功绩、行动力和城市已交易标志由core提供。query不写行情、经验、日期或RNG，不发事件。提交仍校验StateToken、宿主忙状态和权威候选；成功只有一次TRADE_COMMITTED。拒绝和重复提交不获得经验、功绩或声音事实。

新局保存商人行情，`minimum=1, maximum=1000000, step=1`。实际可用上限取原5ca770的当前政治、钱粮库存公式，卖粮保留1粮；不是新的每日/旬成交量限制。任意正成交量使本城本旬已使用，下一旬仍按已核实的原周期恢复。预览的availableMaximum不代表武将/归属/AP已合法，仍以allowed为准。

上限按加经验前当前政治计算；合法成交先政治经验+5（3000封顶）并刷新能力，再用新政治做原整数报价。买粮向下取整；卖粮报价按原负粮量分支取整，再按原金币100000封顶实际入账。24组原上限→XP→刷新→报价→资源块已执行，验证12种卖粮上限情形的原报价超过剩余金币空间时实际钳制；不是根据Java公式推断。

DTO新增 `nativePricing, marketRate, pricingPoliticsBefore/After, rawGoldQuote`，保留旧Quote构造器ABI。nativePricing描述来源方程/状态模式，不证明完整PC随机流、官方剧本或MOD启用。marketRate及pricingPolitics在旧模式为-1；人物经验/能力真实变化仍取Effects。rawGoldQuote是加经验后整数方程的原金额；quotedGold是实际扣款/封顶入账金额，确认和资产变化必须使用它及Effects。pricePerThousand是1000粮单次方程报价，不能以单价×数量替代完整报价；非整千小额可能报价0且正常消耗一次行动/AP、加经验功绩。

未选择执行武将时native模式尚无有效报价，即使quantityValid=true，也不能把quotedGold=0当作合法免费交易。城市rate=0或数据不可报价时明确拒绝MARKET_RATE，不在查询/读档自动初始化。无武将、未知操作、非法量和宿主/版本错误保留原输入。

经济委任与Campaign AI在native模式使用正常预览的上限和完整整数报价，保留既有策略的库存/留金目标；没有据此宣称PC AI策略已对齐。新行情禁止无执行武将的旧foodPrice(city,buy)查询，旧模式函数保持原行为。

## 行情与保存

ScenarioData的新局初始化使用原12月表，城市行情随局保存；普通月初按原30—70及40%/50%/两次判定等分支更新，瘟疫/蝗灾优先于丰收。原外层day1 guard36组、August清丰收bit2的月份/城市504组，以及原天气→逐城月结→价函数的调用顺序已复核。清丰收后的设施通知未执行，完整天气/设置/逐城忠诚/月结仍不宣称闭合。

新格式v35在v34基础/成长/XP/current段之后追加有标记的行情段：据点ID、byte域rate、丰收标志及已处理的月时钟。正常World旬推进在实际天气状态更新后执行一次月价，重复tick不再掷随机数。query和serialization不补价格，不重算历史月价，不读取PC目录。

生产价格分支使用现有保存的Strategy SplitMix64随机流接口，遵守源分支的一次/两次抽取，不新增独立商人RNG。原全局32位LCG、全部系统的共享流/顺序及项目现有灾害/丰收概率和寿命仍未对齐，列为P05/P10未完成；不能把该差异改名为移动端简化或把分支一致称为全局原版一致。城市初始化/遍历按工程稳定ID，完整官方来源ID及启动顺序仍待D01/D03闭合。

旧v31—33不反推基础值、旧数值/旧价模式保持并写v33；旧v34保留人物base/growth/XP/current及旧价模式、写v34，不猜填已经丢失的历史行情。R25实际JVM与ART的v34夹具分别保留，原JVM生产jar和候选的四次普通交易/四旬共8份完整存档逐字节全等。v35输入严格校验行情标记、条数、ID、时钟与byte域，不静默搬单位、删档、钳制读入金币或迁移存档。

作者/兼容金币高于100000仍保存原值。native模式买粮允许实际扣款，卖粮不能再入超额金币；这属于超出原已验证库存域的兼容边界，不据此扩大PC资源域一致性的声明。
