# 武将自定义编辑器：使用与并行集成

## 边界和基线

开发基线为 `83530fbac7d04df9cbeacc293f627ce51fa47bc6`。开始检查时，只有进行中的地图编辑器 PR #58 尚未合并；#57 已由另一开发流程合并。本分支不合并 #58，也不自行合并武将 PR #59。

人物配置属于**新战局内容**。编辑、导入或删除模板不热修改当前战局；历史资料 TSV、地图地形、据点坐标、七格城市规则、港口规则和美术资产均不因本功能改变。

应用仍使用主线版本号 0.66.0，不与并行地图分支争用版本号。实际构建源码由应用 `BuildConfig.SOURCE_REVISION` 和构建产物 `SOURCE_COMMIT.txt` 标识。

## 手机操作

1. 开始页点击「武将自定义 · 模板与投放」。已有战局可从菜单进入「武将自定义 · 新战局模板与投放」。
2. 「新建武将」进入五页编辑：基本资料、能力适性、特技性格、人物关系、剧本投放。
3. 姓名与 UUID 分离；输入五维（0—100），选择六类适性（C/B/A/S）、实际单特技、性别、性格、话术、相性、义理及出生/登场/预计没年。0 年表示未知。模板保存基础能力，不保存宝物、培养、关系编队加成或手填攻防。
4. 头像可选现有图集，也可点「手机图片」使用系统文件选择器，预览缩放、水平/垂直裁剪和旋转，确认后保存为 256×256 PNG。损坏头像回退默认头像并在编辑页提示；启用或导出缺失头像时须先修复。
5. 人物关系使用历史 ID 或自定义 UUID 搜索添加。先保存两个新人物，再建立关系。父母、配偶、结义、亲爱、厌恶使用正式 Relations 规则。保存和开局均会校验；关联自定义人物须一起启用，不会悄悄删掉关系。
6. 「保存模板」产生新修订；「草稿返回」保留尚未完成的文本，包括暂时留空的数字。重新启动后可恢复草稿。
7. 「剧本投放」选择剧本，添加人物，选择加入已有势力、在野或未登场，以及**实际剧本中的有效驻地**。打开「本剧本启用自定义武将」，执行「校验并预览实际战局」，再保存配置。
8. 返回新建游戏，选择同一个剧本和玩家势力。初始化时解析已启用方案，武将作为普通 World.Officer 参与内政、人事、编队、战斗和 AI。显示的攻防预览也调用正式 Combat 入口。
9. 模板库「导出 / 分享」通过系统保存对话框输出 ZIP，再分享文件；「导入数据包」先预览，再选择跳过同 ID、更新同源或作为新人物。导入的新方案默认关闭，须检查并重新启用。

历史复制和覆盖不同：「历史复制 / 覆盖」中的复制创建新身份，不复制亲属、事件身份、职务或当前任务；覆盖保留历史 ID，只作用于明确选择它的新战局。历史覆盖保留原归属和职务，不替换君主、军师、太守。两个配置同时覆盖同一个历史 ID 会阻止开局并提示选择。

删除模板会列出关系和投放引用。可取消，先手动更换引用，再删除；也可明确确认在一次库事务中清理引用后删除。头像采用保守保留策略，不随模板删除而误删共享资源。

## 存储与数据包

- 应用私有命名空间：`files/customOfficers/library.json`、`files/customOfficers/portraits/<sha256>.png`。与 `customMaps` 分离。
- 库格式 `sg11-custom-officers`，模块版本 1，库 UUID / libraryRevision；模板 UUID、修订、持久化 runtimeId、源身份、历史目标指纹；每个剧本一个投放方案及稳定投放 ID。
- 数字 ID 从 100000 起单调分配，不以名字、数组下标或哈希值作为身份。库最多 1000 模板；引擎总武将上限仍为 10000。批量回归包含 400 位新武将。
- AtomicFile 提交单一完整 JSON；库修订阻止过期页面覆盖另一页面的修改。旧 `.sgof` 模板一次性迁移到此库；原局内 PK 的新建/模板读写也使用这一个库，旧文件不继续作为第二个可写库。
- ZIP 包含 `manifest.json` 和真正的头像文件。格式和基础资料修订随包保存；历史覆盖还核对目标 ID 和原姓名指纹。
- 输入图上限 8 MiB，解码下采样；最终头像 256×256、最大 256 KiB。库清单最大 16 MiB，ZIP 压缩和解压内容均最大 20 MiB；拒绝异常路径、重复路径、超限、损坏 PNG、摘要不符、缺失头像、非法数值和悬空引用。截断 ZIP 缺少有效尾目录时拒绝导入。
- 导入先建立完整 ID 映射，再重写包内关系和投放引用。复制包含历史覆盖时，包内 `h:<id>` 关系也重映射到相应的新人物；同一历史 ID 存在多份候选则拒绝歧义。异源同 ID 不能用跳过或更新静默绑定到旧人物。
- 同一包、同一导入策略保存来源映射；重复复制导入不不断增加重复人物。不同策略是不同的显式操作。
- 已有同剧本方案不会被异源导入或复制模式静默合并；导入预览会明确说明保留本地方案，用户需手动为新增人物配置投放。相同库的同源更新可以替换本库方案，并关闭启用状态。
- 失败前已校验并写入的内容寻址头像可能作为未引用资源保留，但人物与关系库不会半提交；不会删除可能被并发页面共享的头像。暂不提供自动垃圾回收。

## 存档和初始化组合接口

全局 `SaveCodec.VERSION` **保持 32**；沿用主线既有 31/32 读取支持，不声称能读取主线已不支持的更旧格式。

`World.extensions` / `SaveExtensions` 在现有编码末尾增加可选、长度界定、分命名空间的数据段。没有扩展的普通 v32 存档编码不变。未知命名空间可读写保留；不是让每个模块自行修改全局版本。

`customOfficers` 模块版本 1 保存启用定义及投放的配置快照、实际人物 ID/修订与头像字节。普通武将状态、关系、培养、部队、人事身份继续由正式存档字段保存。头像不依赖模板路径或临时 URI。修改/删除库后，旧战局仍以其自身快照读档。人物配置和头像总快照上限 8 MiB，过大时开局前明确拒绝。

Android 接入入口：

```java
World resolved = /* 基础剧本 + 已完成的自定义地图/据点解析 */;
World newGame = CustomOfficerSetup.apply(context, resolved);
// 然后 activateWorld、正式存档；失败不覆盖当前战局。
```

`CustomOfficerPlacementUi(Activity, World resolved)` 接收实际启用据点集合所在 World，不读取固定城市表，不依赖地图编辑器私有类。当前 main 中在 ScenarioCatalog.load 之后应用人物配置。

双方集成顺序应为：基础剧本 → 地图修订 → 有效据点 → 人物/历史覆盖解析 → 关系和投放校验 → 激活新局。地图任务应把已解析 World 传入上述两个边界。缺失驻地阻止错误开局，不默认投到第一个城，不删除人物。

**未合入、未实际联调地图 PR #58。** 保存任意 `customMaps` 字节并往返只是可组合扩展机制测试，不代表地图编辑器联合验收。

```sh

bash scripts/verify-custom-officers-android.sh
```

核心回归覆盖实际巡察、行动次数、登用、编队、攻防、百出消耗、真实攻击、AI 行动、关系、年代、历史隔离、非连续据点 ID、容量和存档。特技表来自现有 Skill 枚举，覆盖清单按实际规则代码引用校验；标记已接入仅表示此项目存在相应代码，不代表每项原版效果均百分之百还原。

Android 脚本安装正式 APK 和测试 APK，在 API 29 模拟器操作实际编辑控件、头像裁剪、关系选择、投放及正式新局入口，再执行正常玩法命令和强制停止后的重启读档；产物包含运行日志和实际截图。图片输入使用真实 provider URI 调用正式 Activity 返回处理器，不冒充已手点完所有厂商系统文件选择器。未进行实体手机、多系统版本或地图 PR 组合验收。以具体构建的日志、退出结果和 `SOURCE_COMMIT.txt` 为准；构建成功不单独代表 Android 测试通过。

测试人物、图片、地图和极端数值只在 test / androidTest 中产生，不写入正式默认资料。

## 本次收尾与全量回归边界

- 人物 ZIP 经 `OfficerPackArchive` 同时检查尾目录、本地条目、文件名、偏移、长度与 CRC；拒绝截断、分卷、ZIP64、加密、异常路径及超限解压。除有清单的 ZIP 外，旧 JSON 配置入口保留。新增纯 Java 数据包回归及 Android 库原子性回归。
- 义理、话术掩码、分配器和修订号必须为真正整数；来源标识须为 UUID，不再接受 JSON 小数的隐式截断。
- 旧 CoreTest 行军检查避开会自动进驻的城市占地，回城检查先到达合法占地。安卓势力选择回归按稳定的“选择势力 · 曹操军”无障碍描述定位，不要求显示文案退回旧势力名。
- `scripts/audit-officer-baseline.py <main-worktree>` 以相同现行测试和 fixture 分别编译 main 与候选正式核心，记录每一项历史套件的退出状态与首个异常。对新增/改变的失败和超时失败，不删除原 `test-core.sh` / Gradle check，也不把已有失败包装为全量通过。
- 旧回归还包含早期存档迁移、单格据点 fixture 和旧 AI 行为预期等问题。本轮不回退现行地图/存档规则来迎合过时测试；具体范围以本次构建的 `legacy-audit/comparison.json` 和日志为准。
