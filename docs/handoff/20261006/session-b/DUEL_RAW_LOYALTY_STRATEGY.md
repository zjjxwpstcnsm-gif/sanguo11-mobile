# 原始忠诚保存策略（B WIP）

原支援函数508890读取人物byteAC，页面属性23会封顶100。例如源0/native116：raw120、property100。因此不能把页面忠诚100传入原支援，也不能在原值变更后从显示值反推。

## 明确新局

`pc-duel-raw-loyalty-v1` / PDL1只在PcScenarioOpening建立。按已保存sourceId/sourceSHA/sourceVariant/EXE和稳定officerId/nativeId连接PDB1的670原值；同时记录当时工程World的所属、显示值与trusted。670是映射域，不能据此称670全有效或激活其他人物。

原值0–255独立于显示值0–100，保存读取不会加载当前目录或重填原值。known PDL1损坏、重复、来源不符或trusted与当前所属/显示值不一致拒绝保存；未核实记录保留最后原值和unknown标志，不能作为当前原真值消费。

## 当前变更

工程褒奖、宝物赏赐、授官、忠诚下降、归属变化、继任、编辑等，在变更前使相应记录unknown；即使显示100→100，也不能静默保持raw120。这些命令的原byteAC变更尚未闭合，unknown是待取证边界，并非已经还原。

独立核实的原同城登用、原舌战登用终局，可以在原setter结果已计算、所属已变更后记录确切新值（如94），再次建立trusted。原人控单挑输入只消费该保存内的确切原值；不再要求原值等于显示值，也不从原人物初始表覆盖当前记录。

## 旧档

31–39已有档缺失该namespace时保持缺失，修改命令不添加它。未来/opaque内容保持原字节、原行为，不猜schema。不存在恢复时自动采用，也不改变旧人物身份、base/growth/XP/current、双RNG或其他已存规则策略。
