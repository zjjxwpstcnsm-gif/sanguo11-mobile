# 全局规则｜原生 PC 风格 3D 路线

本文件优先于本包阶段细则；用户本轮更具体的指令优先。适用 R00–R18。

## 1. 这是正式开发，不是方案或演示任务

仓库：`https://github.com/zjjxwpstcnsm-gif/sanguo11-mobile.git`。
目标：保留现有玩法、地图拓扑、官方/自定义剧本、武将编辑、地图编辑、存档与原生 UI，以不依赖 Unity Editor/Player 的 Android 原生渲染路线，改善至接近 PC《三国志11》的连续山河、建筑、部队和整体彩墨观感。

每阶段必须修改真实运行路径中的源码或正式资源，执行验证、构建本阶段 APK、commit、push，创建或更新真实代码 PR，并复读远端确认。只写文档、生成空接口、摆几个立方体、离线效果图、用旧 APK、只在样例 Activity 显示都不算完成。

## 3. 锁定原生路线，不再做一次引擎迁移

已读源码确认现有 `FilamentMapView` 使用 `Engine.Backend.OPENGL`，依赖 Filament 1.56.0。默认优先复用这一 **Android 原生 OpenGL ES 后端**，修改连续地形、资源和表现系统；不是重新启用 Unity，也不是要求手写所有 GPU 底层。

R00 必须记录唯一后端决定。只有复现了 Filament 本身不可修复/不可在现有环境构建运行的具体阻塞，且有对比证据时，才允许在本路线内以 `GLES30 + GLSurfaceView` 替换 GPU 适配层。不得仅凭“画面不好看”“觉得轻量”重写。候选替换必须尽早显示同一真实地图并通过坐标/交互/生命周期回归；若无法做到，保留旧工作路径并报告阻塞，不交付空白引擎。

一旦锁定，后续阶段不得自行再切换。Filament 和手写 GLES 不是需要同时维护的两套生产实现。不要在 Filament 拥有的上下文里随意调用 GLES，不要为它再创建第二个 GLSurfaceView 帧循环。

保持仓库现有 Java 17、Android Gradle Plugin、Gradle、SDK 和签名兼容性；编包时 Filament runtime/material compiler 均为 1.56.0。升级必须有实际必要性、工具匹配、ABI/材质回归，禁止复制官网最新版本号直接升级。OpenGL ES 3.1+ 仅作能力增强，不将其特性无条件混进 3.0 基线。

Unity 工程留作历史，不新增 Unity 依赖，不要求 Editor/授权才能构建原生 APK。仅隔离默认入口和构建耦合，不删除已合入的 game-api/game-runtime 和架构成果。不要更换 Godot/Unreal/WebView 或改写规则为 C++/C#。

## 4. 玩法唯一权威与不回退红线

保留 `app -> game-runtime -> game-api + core` 的架构方向和现有白名单。`GameSession` 的唯一权威、session/generation/revision、存读档和回合票据不得旁路。

渲染只消费不可变投影、稳定实体 ID、版本和展示事件。不得持有/修改权威 World，不在 GPU/渲染线程运行 AI 或存档，不把 GL/Filament/Android 对象写进 game-api。旧 compatibility adapter 可逐步收敛，不另造第二套游戏会话。

同一存档、命令序列和规则 RNG，2D/新 3D 在以下方面必须一致：地形类型/通行、六邻接、城池占地、城港关坐标、出征/进驻、战法射程/伤害、围城、收入、爵位兵数、自动行军、回合、兵源/伤兵、军团、剧本、自定义武将、地图编辑、SaveCodec。

本路线不补做新玩法，不擅改地图来迁就画面，不通过减少 AI 势力/部队/地图范围改善性能。纯视觉随机数必须与规则 RNG 分离且稳定。新地形高度只影响画面与拾取，不影响原规则。

## 5. 连续世界的实质要求

逻辑 Hex 不等于一格一个外观模型。连续地形允许技术分块、索引共享或局部网格，但必须共享边界高度/法线/材质场，避免格子形山包、整块纯色、重复岛屿、阶梯河岸。

平滑不能改变玩法：水陆可达性、港口上下船、关卡瓶颈、城市七格和可选格中心不得被视觉“美化”误导。视觉河岸可以细化，但河道不能曲线穿过陆格中心。森林不能覆盖道路/部队/入口。雾可以营造层次，不能遮掉错误来验收。

像 PC 版不仅是换 Shader：必须有合格地形构图、贴图、建筑轮廓、比例、植被分布、部队编队、光照、四季与相机。程序生成资源也要实际导出、加载、截图复核；占位几何不能重新命名为“最终高精模型”。

## 6. 三条验收线分别记录

- **实现/玩法线**：真实路径接入、无新增回归、兼容存档、可操作。
- **视觉线**：同区域/近似镜头的 PC 参考与 APK 实拍对照，缺少参考就标 `REFERENCE_MISSING`，不能说已经与原版一致。
- **设备线**：模拟器实际渲染和 ARM64 真机性能分别报告；软件渲染、主机数学测试、构建成功都不是手机性能证明。

整体状态只用 `NOT_STARTED / PARTIAL / BLOCKED / PASS`。技术完成但视觉/指定设备证据不足用 PARTIAL；缺少关键依赖导致本阶段无法正常交付用 BLOCKED。每个子项用 PASS/FAIL/NOT_RUN/NOT_APPLICABLE，NOT_APPLICABLE 必须解释。

没有 ARM64 真机不必停止所有能做的源码工作，但不能将真机项写 PASS，不能越过最终发布门槛。R09 局部美术未过，可以继续与其无关的交互/测试工作，不能批量复制未达标模板并声称全国美术完成。
