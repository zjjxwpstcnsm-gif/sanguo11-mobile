# 测试、兼容与性能验收

## 1. 最小测试层次

1. **主机契约/回归**：规则状态对等、坐标/边界、连续场、LOD 接缝、网格/水陆约束、资产校验、缓存失效、命令/播放分离。
2. **实际 Android 构建**：app + instrumentation + lint，沿用仓库 map release 和架构边界检查。任务名先用 Gradle tasks 核实，旧 main-style 测试需真实进入执行链。
3. **模拟器实际渲染**：明确 API、ABI、图形驱动（硬件/ANGLE/SwiftShader 等）、画质和内部尺寸，正常启动、剧本、3D Surface、手势、回合、存读档、编辑。
4. **ARM64 真机**：至少一台明确型号做全流程和长稳；正式兼容验收目标覆盖 Adreno 与 Mali 两个实际驱动家族，做不到就标覆盖缺失。模拟器的计时不替代手机数据。

基线比较使用同一命令、同一场景和相同配置；新失败不能与旧失败混在“总计很多错误”里。复现旧失败不等于允许引入新的错误。

## 2. 玩法不变的回放矩阵

同一场景/存档及固定命令序列，在 2D/3D/关闭动画/跳过动画下比较权威状态。根据既有 SaveCodec 或规范化投影计算哈希，含规则 RNG，不包括相机与纯视觉配置。

必含：新剧本与自定义剧本、七格城市六向出入、港口上下水、关卡瓶颈、出征/自动行军/攻击、攻陷进驻、军团、征兵/巡察/生产、下一旬、战报、势力/武将列表、地图/武将编辑及导入导出、普通/旧版/自定义存档。

渲染开关、低帧率、动画倍速、暂停/跳过、Activity 重建与 Surface 重建不得改变权威结果，也不能多发一次攻击/征兵。

## 3. 自动化图形检查

每个代表区固定 seed、相机、时刻、季节、画质，采样 mesh 和真实帧。自动查 NaN、无效索引、边界裂缝、水陆违规、缺资源、帧输出长时间纯背景、内存/资源句柄趋势。

先确保图像是实际 render surface：SurfaceView 截图可按设备能力使用屏幕 capture/PixelCopy/引擎回读，必须等待实际完成。正常 UI 截图没有捕获 Surface 时不能用它判 3D 成功。

SSIM 等允许辅助，但不得把 GPU 不同导致的像素差简单当回归，也不得把色彩变化误当质量提升。保留人工目视结论、图号与缺陷记录。

## 4. 生命周期/故障

应用前后台 20 次、2D/3D 切换 20 次、支持的方向/布局变化、低内存回调、读档/换剧本/编辑导入、用户退出重进、进程被系统杀后恢复。测试只有一条帧循环、Surface/engine 不泄漏、旧 worker 不回灌。

资源缺失/损坏、着色器不兼容、上传失败、能力不足的降级必须能退回可玩界面。native abort 不能靠 Java try/catch 保证恢复；使用下次启动保护、持久化健康标记和诊断，不能反复启动崩溃循环。

## 5. 建议起始性能预算

这些是设计目标，**不是当前游戏实测，也不是所有手机保证**。R00 记录基线；R16 根据可用目标机、API 和驱动冻结正式测试条件；任何预算调整必须保留旧目标和原因。

| 指标 | 初始目标/口径 |
|---|---|
| 标准档 | 30 fps 节奏，真实呈现间隔 p95 ≤ 40 ms，p99 ≤ 67 ms；正式地图正常操作 |
| 高档 | 60 fps 作为选配目标，不保证所有机型；不得牺牲正常档可读性 |
| 卡顿 | 稳定巡航排除加载后，不出现可复现的 >200 ms UI/呈现停顿 |
| CPU 资源生成 | 不占主线程，增量/有界队列；渲染每帧上传起始预算 ≤ 2 ms，实测调整 |
| 进程峰值 | 标准档目标 PSS ≤ 384 MiB；同时报告 Java/native/GPU 估计口径，不相互冒充 |
| GPU 资源 | 起始估算预算 ≤ 128 MiB；纹理/mip/几何/深度/帧缓冲均计入，实际驱动分配可能不同 |
| 包体 | 常规可安装单独 APK 起始目标 ≤ 100 MiB；报告 universal 和 ARM64 实际大小，不混比 |
| 首次可玩 | 代表机冷启动进入地图起始目标 ≤ 10 秒，拆分启动/存档/资源/首次呈现 |
| 长稳 | 30 分钟真实游戏混合操作/回合/视角巡航；PSS 热身后无持续增长趋势 |
| 温控 | 记录 thermal 状态和降级恢复；降级不丢玩法对象，不把 UI 一同降成模糊图 |

计时来源要准确：Choreographer 回调间隔不是呈现 FPS；提交耗时不是 GPU duration；Java heap 不是总进程内存；计算 mesh bytes 不是实测 GPU 内存。平台无可靠数据时标 ESTIMATED/NOT_AVAILABLE，不能用另一个数偷换。

## 6. 压力场景

用现有实际全国剧本制造可复现压力：密集城市/林区、水港、山口、大量真实部队、战斗特效、镜头连续缩放/旋转、边播放边拖图、跨区域 streaming、编辑大型 patch。压力输入可自动构造，但要标出与真实剧本的差异，不能只测一个三角形。

全国地图要分块、视锥裁剪、LOD、上传限流、引用计数和预算驱逐。不要一次性缓存全图所有 LOD 的数组，也不要每帧扫描全图。变更一格应只重建有界依赖邻域。

## 7. 构建及证据

沿用 `./gradlew` 和现有 JDK/SDK；常见目标 `:app:assembleDebug`、`:app:assembleDebugAndroidTest`、`:app:lintDebug`，但以真实 tasks 为准。PR/CI 权限审批不通过必须明确，不通过跳过必需检查绕过。

每次证据都含命令和退出码。制品 manifest 模板见 templates。未执行的项留 NOT_RUN，不能用前阶段证据替代本阶段受影响的验收。无关历史证据可引用但写明 SHA/范围。
