# 范围与明确决策

## 包含

正式原生地图渲染、连续地形、约束岸线、水体、模型/贴图生产与加载、城市/港口/关卡/设施、植被/道路/山石、部队编队/动画、既有战斗展示、相机拾取、网格与势力开关、原生 UI 协调、编辑器/存档接入、四季/彩墨光照、全图覆盖、性能/兼容、APK 与代码交付。

## 不包含

新增/重写规则、全国地形数据考据重制、官方剧本数据补全、改 AI 或精确公式、单挑/舌战高精人物动画、音频系统大改、多人联机、PC/浏览器移植、Unity/Godot/UE 工程重启、复制未获授权的商业游戏资源。

若发现玩法缺陷，记录并复现；只有本阶段改动引入的回归应在本阶段修复。渲染任务不能以“顺便修规则”改变平衡或地图。

## 固定决策

- 基于最新 main 的既有架构，不回退旧 main。
- 分支 `agent/native-pc-visual`，串行推进；默认同一 Draft PR，不自动合并。
- 默认复用现有 Filament/OpenGL；不是另写一套通用引擎。纯 GLES 替代仅由 R00 的实测阻塞触发。
- 存在 2D 回退，但不能把自动回退当成 3D 已通过。R18 前不强行默认 3D；切换策略按验收结果决定。
- 不保证“普通手机随便几千棵树无压力”“换 API 就能达到原版”。性能、美术和可操作性分别有门槛。
- 没有资产/参考/真机就明确缺项，不因阶段编号推进自动清债。

## 工程完成 vs 交付完成

实现写完、构建可用、模拟器通过、ARM64 通过、视觉通过、性能通过、远端可取是独立字段。阶段范围不涉及某一门槛可以说明不适用；涉及但没做只能 NOT_RUN/PARTIAL。

最终路线完成需要 R18 的综合验收。R09 才是“局部样板”而不是“全国达到 PC 版”；R15 是全图覆盖而不自动代表性能过关。
