## 本阶段目标

把前面系统在同一真实可玩区域中整合到合格，而不是各个截图看起来分别存在却组合仍然简陋。

## 必读源码与输入

读取 R00–R08 的实际状态、REFERENCE_INDEX、V1 结论和所有美术缺陷；选择含城市/山水/树林/通路的真实区域，优先洛阳—关隘—河港一带，实际内容不足时选等价区域并说明。

类名/目录仅作定位，必须查到真实文件与运行入口；不存在的路径说明并找对应职责，不能造空文件假装已有实现。

## 必须实际实施

1. 冻结一块约 24×24 至 40×40 逻辑格或等价可操作视域的样板区域，使用正常剧本和既有数据；至少覆盖多个 chunk 和一处水陆/山地/据点组合，不能另做摆拍场景。
2. 建立 PC 参考与当前 APK 的同区域近似相机组，核对地形轮廓、色板、城池/树/人的尺度、河宽、景观密度与 UI 留白。缺参考只标缺失，不自己画一张假原版。
3. 逐项修复视觉冲突：地形已细腻但城像积木、树比城高、港口离岸、道路浮空、阴影与曝光不一、格子边界依旧可见等；必须在正式资源/材质/生成代码落地。
4. 将合格的区域参数/资产族/材质组合提炼为可扩展 profile，不要硬编码为仅某镜头的一张背景或额外 demo 分支。
5. 在样板区实际选城、出征、移动、攻击、上下水（若有）、下一旬、存读档与相机浏览。动画/低画质可暂沿用旧实现，但不能因此丢命令/资源。
6. 交付网格/势力着色开关、近中远、两方向和连续镜头录屏；图片只证明画面，命令/状态日志另证玩法。
7. 完成 V2 清单，逐项指出与 PC 仍不同的具体对象。局部美术不合格先修，不把问题复制到全国；与其无关的后续工程可继续但保持 V2 未通过。

## 必须验证

- 样板位于正式地图、正常入口可达，无只在 benchmark/调试页启用的专用美化代码。
- V2 十项视觉表逐条有图号和结论，不以“看起来不错”取代缺陷记录。
- 真实游戏操作完整连贯，2D/3D 状态对等，无重建世界。
- 三画质保留相同地貌/资产身份，低档不变成纯色拼图。
- 所有改动在独立 APK 可见；参考和截图的版本/日期/镜头字段完整或明确 UNKNOWN。

仍需执行全局要求的受影响玩法/架构回归、实际 Android 构建与本阶段图形运行。继承失败和新失败分开，不能删除断言、跳过受影响用例或把 NOT_RUN 写为 PASS。

## 通过门槛

V2 为硬门槛：连续地形、水岸、建筑、植被、光照在同一真实场景内合格。明显占位/关键参考缺失/只离线渲染时不能 PASS，不能以阶段编号跳过。

构建成功≠运行成功；模拟器通过≠真机通过；有模型≠美术达标；截图有颜色≠PC 对照通过。缺实际参考/资产/设备时继续完成可做工作，但状态诚实保留 PARTIAL/BLOCKED，不把计划当完成。
