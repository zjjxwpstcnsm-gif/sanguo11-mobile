## 本阶段目标

把现有正式部队表现升级成能识别兵种、方向和行动状态的 3D 编队，不改变规则与路径。

## 必读源码与输入

读取 R09、FieldAssets/UnitVisual/UnitMotion/UnitAnimation、真实兵装/运输/水军类型、TurnJournal 路径与既有动画/LOD 约束。

类名/目录仅作定位，必须查到真实文件与运行入口；不存在的路径说明并找对应职责，不能造空文件假装已有实现。

## 必须实际实施

1. 汇总所有实际兵种/装备/船型/器械/运输类别及已有资源，逐项标已合格、需升级、缺失；不只做一个步兵模板就称全部完成。
2. 通过 R06 流水线提升模型轮廓、武器、马匹/器械/船体、纹理和旗帜；统一与城市/树木的屏幕尺度。必要的精细度用近景 LOD，远景保持类别可辨。
3. 完善待机、行军、攻击、受击/撤退或项目既有状态的动作；刚性部件与骨骼按已锁定格式使用，明确实际技术。骑兵腿/马体、车轮/投石臂/冲车、船桨等要有真实运动。
4. 将视觉姿态/动画 phase 与权威路径和当前播放事件绑定；脚/车轮贴地、水军贴水，转弯平滑但不抄近路穿山/城墙。根运动不改变格坐标和行军完成时点。
5. 兵力变化驱动代表性编队规模/损员，不要求一兵一模型；分组/合批/实例化选合适策略，不能每帧 CPU 全量重建所有士兵网格。
6. 选中范围/旗帜/数字标签随展示位置同步，点击移动中编队映射回同一稳定 unit ID，命令仍由现有权威验证；敌我视觉标识不得依赖只有颜色。
7. LOD/动画降频/远景代理使用滞回，避免缩放时编队跳位置或重新播攻击；换兵装、上下水、死亡/撤走、读档/跳过播放正确收敛。

## 必须验证

- 全类别资产映射、动作状态切换、LOD/phase/确定性测试，缺失项显式列出。
- 同一行军/攻击序列在无动画、正常、倍速/跳过下权威状态一致。
- 实际平地/山路/城门/港口/弯道的脚滑、穿模、漂浮、朝向和水位目视检查。
- 大量可见部队测试资源共享、提交量、帧时间，区分 CPU 变形与 GPU 动画。
- 实拍至少步兵、骑兵、器械/运输和水军的移动/攻击；真实类别不足用标注过的测试存档。

仍需执行全局要求的受影响玩法/架构回归、实际 Android 构建与本阶段图形运行。继承失败和新失败分开，不能删除断言、跳过受影响用例或把 NOT_RUN 写为 PASS。

## 通过门槛

现有游戏全部正式部队类别有可用且明确状态的表现；主类型仍是占位几何或只有模型没有行动姿态时相关项不通过。

构建成功≠运行成功；模拟器通过≠真机通过；有模型≠美术达标；截图有颜色≠PC 对照通过。缺实际参考/资产/设备时继续完成可做工作，但状态诚实保留 PARTIAL/BLOCKED，不把计划当完成。
