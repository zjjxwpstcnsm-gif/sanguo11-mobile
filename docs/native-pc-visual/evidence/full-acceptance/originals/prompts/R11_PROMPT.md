## 本阶段目标

让现有攻击、战法、火焰和反馈具有一致的 3D 时序与可读性，且无重复伤害或演示卡死。

## 必读源码与输入

读取 R10、TurnJournal/CombatVisual、已有战法/受击/暴击/火场/据点反击/军乐恢复等正式事件和 UI 反馈。

类名/目录仅作定位，必须查到真实文件与运行入口；不存在的路径说明并找对应职责，不能造空文件假装已有实现。

## 必须实际实施

1. 盘点实际可产生的表现事件，建立事件 ID→效果/数字/镜头/音效（如已有）映射，复用类型化字段，不解析中文战报来驱动规则。
2. 升级箭矢/投射、枪戟/骑兵冲击、器械、船战、火焰烟尘、受击闪烁与必要计谋效果；效果在真实目标/地形位置，不穿地或始终贴屏幕中心。
3. 动画节奏与 TurnJournal 路径/impact 对齐，伤害数字来自实际计算结果；特效何时结束不能决定伤害/攻陷是否执行。暂停/倍速/跳过立即、安全收敛。
4. 粒子池/mesh/贴图合批有界，透明排序与深度处理清楚；降低质量可削粒子，不漏敌我状态/伤害反馈。远景不必播放所有细粒子。
5. 保留暴击头像/战法高光、设施反击、战报和实际收益变化显示；同一个事件不能因 view 重建或相机进入视野重复播放/叠伤害。
6. 火场/持续状态从正式状态重建，world replacement/读档/后台恢复后不残留旧火，也不把展示快照写回存档。
7. 避免强制镜头运动和慢演示阻碍操作；镜头可打断，跳过不需等全部 GPU 效果自然结束。对已有音频只同步必要触发，不扩大为新声音工程。

## 必须验证

- 每个实际事件类别有覆盖测试和真实截图/录屏，事件未出现的测试不能算该类已通过。
- 正常/暂停/倍速/跳过/离开视野/重建界面下比较最终权威状态、事件次数和自动存档。
- 火场跨读档/回合、攻陷/单位消失、播放取消时清理正确。
- 多组同时特效下池容量/内存稳定，无 OOM/漏回调/无限播放。
- 低/中/高档都能辨认攻击对象和结果，数值与战报一致。

仍需执行全局要求的受影响玩法/架构回归、实际 Android 构建与本阶段图形运行。继承失败和新失败分开，不能删除断言、跳过受影响用例或把 NOT_RUN 写为 PASS。
