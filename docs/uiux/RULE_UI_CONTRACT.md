# UI 所需权威预览契约（交玩法会话）

2026-10-03，基于共享基线 `baseline-20261002`；UI工作目录 `/Users/paopao/workspace/sanguo11-mobile-uiux`。这是接口需求，不是已实现的规则；本会话不修改 core/game-api/game-runtime、剧本或转换工具。

## 优先：出征预览与实际提交共用校验

继承代码 `Army.deploymentPreview` 只返回出城位置/临时部队，未执行 `Army.deploy` 的完整校验。`DeployWizard.error()` 因此在 UI 内重复若干条件，且会把不同失败都归为“无合法出征格”。请在权威层提供只读预览；命名和所在模块由玩法会话确定，以下是必须满足的语义。

输入：当前会话身份/局面版本、据点ID、主将ID、有序副将ID（0–2）、兵装、舰船、兵力、携粮、携金。输入范围之外的数据也返回明确错误；不能让 UI 为探测有效性试执行命令。

输出：

- `allowed`、稳定原因码、面向玩家的原因文字、对应字段（city/leader/deputies/weapon/ship/troops/food/gold/target/global）。原因优先级与正式提交一致。
- 权威给出的可选数量范围、库存/统兵/保留量约束、行动力成本、兵装舰船及钱粮消耗、留守量。UI 只格式化和展示。
- 合法时的出征格、出城已耗移动、本旬剩余移动、部队攻防、适性及后勤预测。现有核心查询可复用；不在 UI 再写公式。
- 预览所属 sessionId/revision，供 UI 在确认时发现过期；最终提交仍在权威层重新校验。

只读保证：任何有效或无效预览都不能修改 World、RNG、下一部队ID、reports、日志、事件队列、行动力、武将状态或文件；同一版本相同输入得到相同输出。不因反复键入、切页、取消而推进随机数。不要通过执行后回滚获得预览。

验证：对合法/缺粮/库存不足/重复副将/非闲将/预留资源/被封锁出城/过期版本逐项比较“预览失败原因”和“实际正式命令失败原因”；所有预览前后完整捕获字节相同，正式成功只提交一次。

## 随后：建设预览

输入：会话/版本、据点ID、地块、设施类型、执行武将ID。

输出：合法性、稳定原因与字段、金/AP、权威工期、占用武将、完工等级及效果、取消建设的资源与人员结果。与正式 build 共用校验。UI当前继承的 `politics>=80 ? 2 : 3` 工期文字需要替换为权威返回，不能继续扩展此分支公式。

## 随后：运输草稿摘要

现有 `transportError/transportPreview/shipCargoError` 可继续作为正式原因来源。建议返回结构化钱粮兵装舰船消耗、目的地容量、运输旬耗/可支撑旬数；第十一批已删除继承的ration近似与容量硬编码，当前输入仅以出发城库存为范围，预览时调用现有transportError/transportPreview/shipCargoError；仍需结构化DTO提供准确可选区间与字段级原因，避免玩家到确认时才发现容量限制。显示预测与最终执行条件应明确一致；航路/不可达由权威查询返回。

## 集成方式

玩法会话实现并给出接口及对应增量提交后，UI会话在独立目录接入、移除相应重复校验/公式，并重新执行实际触屏确认/失败/取消/重复点击测试。本文件不授权 UI 私自实现规则，也不代表这些预览已验证。无接口期间继续可独立完成的布局、草稿、搜索、键盘和返回路径；正式命令始终只经 GameSession 提交。

## 后续优先契约：生产、交易及任务管理

当前ArmyUi与CampaignUi仍有继承的固定AP10、粮食交易总价与旬剩余额度等UI计算。请按已有Preview/Command形式分批提供，不由本UI会话扩展规则。所有输入包含StateToken，错误含稳定code/field/detail；预览保持完整局面、RNG、事件和文件不变，正式提交重验且只增加一次revision。

1. Production：输入cityId、actorId、基础兵装/器械/舰船类型；输出可用设施与本旬剩余次数、金/AP成本和剩余量、实际产量、完成后库存及容量、占用旬数、即时入库或制造任务、任务中止条件。取消制造另接taskId，返回退款/武将本旬行动/库存变化；不要让UI自行推算工期或把“1件”写为所有类型的常量。
2. Trade：输入cityId、actorId、买/卖、粮食数量；输出可选最小/最大/步长、真实总价、金粮前后量、旬交易额度及剩余量、金/AP/武将占用、设施或商人不可用原因。数量不合法时也给可选区间；UI保留原输入并标红，不静默修正。
3. Mission/Construction管理：输入任务或设施ID、redirect/cancel/demolish等操作及目的地/执行人；输出合法目标、费用/退款、当前货物和人员的最终去向、是否立即生效或继续等待、操作后不可逆影响。改道不能由UI用直线距离猜测耗时；卸货等待与失败必须区分。
4. 高级外交：援军请求、劝降、交换俘虏、结束援军沿用普通外交的成本/预留/退款/抵达阶段语义；输出有效目标、金数量区间、实际资源承诺、条件概率或不可预测说明。UI不能把首次接受检定写成最终成功概率，不提前抽取舌战或使节结果。

共同性能要求：请提供宿主串行队列上的可取消异步预览或同版本预热契约；旧请求结果必须携带输入身份/StateToken，UI可丢弃过期结果而不改变权威状态。不能要求UI在后台直接调用当前串行GameSession，也不能要求UI另建权威World。以上是待实现接口需求，未接入、未验收。
