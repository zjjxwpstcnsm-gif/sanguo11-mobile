# 第十四批：Q运输与普通外交权威预览

## 范围与隔离

独立UI目录，源码基于8e1d5f7加本批变更。依赖冻结Q的377份模块文件全部SHA一致，构建使用out/uiux/contract-v4.init.gradle；相对P仅Army、CampaignAi、Districts和CoreTest变化，API不变。root core/API/runtime/data/内容工具504份继承文件未改；383项companion输入及tar内字节核验一致。不写原项目、不操作5554、不启动Wine、不修改美术。

CargoWizard用TransportPreview展示数量范围、源库存、目的空位、实际AP、路线与耗粮预测、卸货等待及人员返程，正式派遣走TransportCommand。超限保留原输入；连续编辑合并100ms后在宿主串行线程查询，不是后台异步。反馈与条件详情同行，减少横屏遮挡；兵装与舰船拆为独立页签，切换保留全部数量。目的地容量不足提示可能等待，不能把核心允许的派遣擅自禁止。

CampaignUi亲善、停战、同盟、解除协定改用DiplomacyPreview/Command。期限、费用、目的地、单程/往返和效果取自DTO；首次接受检定不写成最终成功率。失败禁用确认，返回修改保留执行人的查询和选中；系统返回与期限/势力的上一步均有实际测试。高级外交没有在本批切换。

## 真实失败与修复

- p14-01早期运输功能检查通过，但目视发现横屏首项被底部独立按钮挤压；反馈/条件改同行，并新增实际数量编辑断言。p14-03的69项通过作为中间记录保留。
- p14-02误把原生AlertDialog列表项当成可点击TextView，测试selector失败；改为定位后真实触摸行，原失败及读档恢复保留。
- p14-04外交240秒超时；恢复完整局面/RNG比较通过，截图/finish又超过80秒。p14-07重启host后端后点击势力行未进入命令页，截图仍为名单，恢复也超时。两次系统持续SurfaceFlinger driver stall；单点线程在绘制/等待idle处，不能据此证明Java业务死锁。宿主超时后有UiAutomation断开记录。三个用户文件SHA均核验保持原值。
- p14-08 SwiftShader同APK/分辨率对照仍300秒超时，已验证关系不足禁用及预览纯度。录像SIGINT退出超时，不把其视频称为完整封装通过。新runner在恢复超时后确实停止本设备过期instrumentation并回读auto/manual3，SHA一致。
- p14-11长兵装/舰船合页在14次上滑测试中未找到末项，截图已到楼船但斗舰仍在下方。没有绕过测试改库存；run12将舰船独立成页，p14-13实际切页并编辑末项通过。改前截图保留为cargo-list-before.png。

runner修复恢复超时直接跳过末尾存档校验的问题：异常与恢复证据另存、终止本设备已超时的instrumentation后继续回读，不重写存档。受控subprocess模拟也验证失败仍失败退出且执行后置存档校验；模拟本身不访问设备。

## 性能与限制

host与SwiftShader带外部窗口均出现严重迟缓；SwiftShader时整体设备负载19.32，图形合成/系统服务/录像编码/应用都有明显占用，首次外交预览11807ms。仅自己的AVD切回host加-no-window后完成上述通过路径，保持相同Android分辨率、资源与APK；关闭的是外部模拟器窗口，不是游戏渲染。不操作另一会话AVD。环境及时间不同，不能把改善唯一归因于窗口或宣称真机性能通过。

最终运输预览首次381ms/190ms，外交258ms；同版本重复多为0–1ms，不等于首次不卡顿。外交五旬compute为9535/15528/13108/9380/7366ms，total为10126/16448/14073/10434/8677ms；最终运输两旬compute21920/21508ms、total23110/22619ms。逐势力日志保留，整体流畅性未验收。早期运输视频5秒仍为启动背景，启动等待也不能称为已解决。没有ARM真机数据。
