# 第十六批：AA交易限制与横屏数量输入

## 隔离与基线

独立UI目录、codex/mobile-uiux，基于74072e9。冻结AA的396份模块只复制到自己的out/uiux/contract-20261003-aa，v6 init独立构建，402项companion保存模块、来源manifest、init和4个双ABI原生库。原始受保护core/API/runtime/data/内容工具504文件不改；不写原目录或5554，不清模拟器数据，不启动Wine。应用资源沿用初始638项，不新增美术。

本批AA已限制同城每旬只交易一次，买卖和执行武将共享；港口、关卡不允许交易。报价/数量仍按模型，后续PC价格、功绩等校准不属于本批；不能把旧V同旬买后卖的通过结论套给AA。

## UI变化

商人表单改为“本旬可交易量”，另显示“本旬已成交”原始数量。可用性、失败原因、下一旬恢复均来自正式TradePreview/Command；不以UI计数器管理交易许可，不修改历史正交易量。

通用QuantityControl关闭横屏IME全屏提取，并在空间足够时把数量名称、范围与输入行一起滚入可见区。运输和出征在短视口内将页签和条件说明移入同一滚动区；底部取消/确认保留，键盘收起恢复页签位置。浮动窗口在绘制前检查可见高度，只有变化时重新布局，关闭释放监听；运输另外监听条件说明高度变化。布局是移动端适配。

## 修复过程与保留失败

- p16-01交易97项、p16-02港口43项在较早app/test-run01通过。港口没有闲置执行人时，实际调动曹操到官渡港并推进一旬，再核对TRADE_SITE，避免把缺执行人的错误误当据点限制。
- p16-03运输、p16-04出征在run01暴露真实横屏字段裁切。关闭全屏IME仍不足以保证字段可见，保留FAIL截图/全程录像/正常读档恢复。
- run03/p16-05运输70项通过，但目视发现数量名称滚出视口，后续增加名称完整可见断言和滚动上下文。
- run03/p16-06、run04/p16-08出征在键盘收起后仍停留于紧凑高度；仅GlobalLayout及Insets回调不足，最终改为绘制前按可见高度变化重新布局。没有放宽恢复后切页检查。
- run04/p16-07旋转后切页未成功，停留在详情页，原证据保留；不把它算通过，也不伪称已确定唯一原因。
- 验证辅助命令曾误用不存在的tools/check_architecture.py，未执行检查；后续使用实际scripts/check-architecture.py通过，未修改检查器。
