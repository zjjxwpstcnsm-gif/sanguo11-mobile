## 可复现失败与期望调整

- `TacticalLogisticsProbe.java`同时编译到旧/新代码。旧b75e249输出当前位置(7,15)、粮4950、已耗50但`battlefieldUnit=false`，断言失败；新版同一对象进入真实战场，见`baseline-probe.txt`与`fixed-probe.txt`。
- 水陆战役最初失败于“军团据点之间没有可通行的运输路线”。Districts旧编制只检查陆路；改为水陆连通后，两城零预置部队出发、会合、冲车过狭口、攻下港口的全部断言通过。没有移除原陆战两组断言。
- 多旬地图地块指令最初与“停止自动交付”共用标记导致下一旬停在半路；现在标记仅在行军命令完成后待命，新增跨旬抵达并继续耗粮断言。
- `DomesticTest`与`LogisticsCampaignTest`满仓位置：旧值“进入城市格”，新值“距离城市1格且货物仍在队中”。来源是真实战场占格规则，不删除容量、耗粮和货物守恒断言。
- `SupplyTest`截击：旧独立固定伤害期望改为同一局面调用真实War.attack的完整序列化结果相等，保留缴获/俘虏/粮耗；堵路旧期望“完全不动”改为“不穿占格且不超过4移动”，允许地图上确实存在的绕路。
- 旧测试中当前写入版本期望20→21，仅调整writer版本；真实v20夹具断言仍为20。新升级脚本安装用户上一轮交付的实际APK且校验固定SHA，未用新编码器伪造旧档。

零兵旧兼容货运接入共用地形损伤后，真实移动到毒泉复现凭空出现1兵：原野战损伤的“至少保留1兵”不适用于已是0兵的运输。`ZeroSoldierProbe.java`与前后输出保留；只让正兵力执行毒泉/栈道损伤，新增资源不变与存档断言。

`migration-budget-before.txt`复现真实v20任务已结算本旬、粮4950/已耗50，却在迁移后还可移动4。修复为旧任务本旬已结算或旧格式在途记录没有预算轨迹时冻结当旬移动，下一旬恢复。新增预览不改局面、不能立即再移动断言；不退款、不回退位置，前后输出与探针均保留。
